## ১. রিলেশনাল অ্যালজেব্রা সমতুল্যতা রূপান্তর বিধি (Heuristic Query Rewriting)

একটি SQL কুয়েরি যখন ডেটাবেস ইঞ্জিনে আসে, তখন অপটিমাইজার প্রথমে হিউরিস্টিক নিয়মের মাধ্যমে কুয়েরি ট্রি-কে গাণিতিকভাবে সমতুল্য কিন্তু বহুগুণ দ্রুততর একটি ট্রিতে রূপান্তর করে।

```
                              [ QUERY REWRITING HEURISTICS ]
                                             |
             +-------------------------------+-------------------------------+
             |                                                               |
[ 1. Selection Pushdown (Push Down sigma) ]                         [ 2. Projection Pushdown (Push Down pi) ]
  - ফিল্টারিং শর্তকে ট্রির একদম নিচে ঠেলে দেওয়া।                       - অপ্রয়োজনীয় কলামগুলোকে শুরুতেই বাদ দেওয়া।
  - জয়েন করার আগেই টেবিলের রো কমিয়ে ফেলা!                            - জয়েন ও সর্টিং মেমোরিতে কেবল দরকারি কলাম রাখা।
```

```
Naive Un-optimized Plan:
                sigma_{Users.city = 'Dhaka' AND Orders.amount > 500}
                                   |
                             [ Cross Join x ]
                                /        \
                            Users        Orders
(Massive Cartesian Product: 1M Users x 10M Orders = 10 Trillion Tuples created in RAM first!)

Optimized Plan with Selection Pushdown:
                            [ Hash Join on user_id ]
                                  /            \
           sigma_{city='Dhaka'}(Users)     sigma_{amount > 500}(Orders)
(Filters rows FIRST: 10k Users joined with 50k Orders = Only 500M operations! 20,000x Faster!)
```

### প্রধান ৫টি সমতুল্যতার নিয়ম (Equivalence Rules):
1. **সিলেকশনের কমিউটেটিভিটি:** $\sigma_{p_1}(\sigma_{p_2}(R)) \equiv \sigma_{p_2}(\sigma_{p_1}(R)) \equiv \sigma_{p_1 \land p_2}(R)$
2. **জয়েনের কমিউটেটিভিটি ও অ্যাসোসিয়েটিভিটি:**
   - $R \bowtie S \equiv S \bowtie R$
   - $(R \bowtie S) \bowtie T \equiv R \bowtie (S \bowtie T)$
3. **সিলেকশন পুশডাউন ওভার জয়েন:**
   $$\sigma_{p}(R \bowtie S) \equiv \sigma_p(R) \bowtie S \quad (\text{যদি শর্ত } p \text{ কেবল } R\text{-এর অ্যাট্রিবিউটের ওপর হয়})$$
4. **প্রজেকশন পুশডাউন ওভার জয়েন:** জয়েন করার পূর্বে যে কলামগুলো পরবর্তীতে আর লাগবে না সেগুলোকে আগেই ছেঁটে ফেলা ($\pi$).

## ২. কস্ট-বেসড অপটিমাইজার ও সিলেক্টির গাণিতিক সূত্র (CBO Math)

একটি কুয়েরি সম্পাদনের জন্য শত শত ভিন্ন ভিন্ন এক্সিকিউশন প্ল্যান তৈরি হতে পারে। **Cost-Based Optimizer (CBO)** ডেটাবেস ক্যাটালগ পরিসংখ্যান (System Catalogs, যেমন PostgreSQL `pg_statistic`) ব্যবহার করে প্রতিটি পথের গাণিতিক ব্যয় হিসাব করে:

$$\text{Total Cost} = (\text{Disk Page Fetches} \times \text{Page Read Cost}) + (\text{Tuples Processed} \times \text{CPU Operator Cost})$$

### সিলেক্ট্রি ও কার্ডিনালিটি এস্টিমেশন (Selectivity Estimation Formulas):
সিলেক্ট্রি ($\text{Sel} \in [0, 1]$) নির্দেশ করে টেবিলের মোট কত শতাংশ সারি ফিল্টার শর্ত পূরণ করবে।
ধরা যাক রিলেশন $R$-এর মোট সারির সংখ্যা $N = |R|$ এবং অ্যাট্রিবিউট $A$-এর স্বতন্ত্র মানের সংখ্যা $V(A, R)$।

1. **ইউনিক কলামে সমতা শর্ত (`A = constant`):**
   $$\text{Sel}(A = c) = \frac{1}{N}$$
2. **নন-ইউনিক কলামে সমতা শর্ত (Uniform Distribution Assumption):**
   $$\text{Sel}(A = c) = \frac{1}{V(A, R)}$$
3. **রেঞ্জ বা বৈষম্যমূলক শর্ত (`A > constant`):**
   হিস্টোগ্রামের সর্বনিম্ন মান $\min(A)$ এবং সর্বোচ্চ মান $\max(A)$ হলে:
   $$\text{Sel}(A > c) = \frac{\max(A) - c}{\max(A) - \min(A)}$$
4. **কনজাংশন শর্ত (`condition_1 AND condition_2` - Independence Assumption):**
   $$\text{Sel}(C_1 \land C_2) = \text{Sel}(C_1) \times \text{Sel}(C_2)$$
5. **ডিসজাংশন শর্ত (`condition_1 OR condition_2`):**
   $$\text{Sel}(C_1 \lor C_2) = \text{Sel}(C_1) + \text{Sel}(C_2) - (\text{Sel}(C_1) \times \text{Sel}(C_2))$$
6. **নেগেশন শর্ত (`NOT condition`):**
   $$\text{Sel}(\neg C) = 1 - \text{Sel}(C)$$

## ৩. জয়েন অর্ডারিং ও ডাইনামিক প্রোগ্রামিং (The System-R Algorithm)

$N$ টি টেবিল জয়েন করতে হলে তাদের সাজানোর সম্ভাব্য ক্রমের সংখ্যা দাঁড়ায়:

$$\frac{(2N - 2)!}{(N - 1)!}$$

$N = 10$ টি টেবিলের জন্য প্রায় **১ কোটি ৭৬ লাখ ভিন্ন ভিন্ন জয়েন ট্রি** সম্ভব! ব্রুট-ফোর্স উপায়ে সমস্ত প্ল্যান যাচাই করা অসম্ভব।

```
[ Left-Deep Tree (System-R Standard) ]             [ Bushy Tree (Complex Distributed) ]
                  Join                                              Join
                 /    \                                            /    \
               Join    T4                                       Join     Join
              /    \                                           /    \   /    \
            Join    T3                                        T1    T2 T3    T4
           /    \
         T1      T2
(Pipelining-friendly, intermediate results never saved to disk!)
```

### প্যাট্রিসিয়া সেলিঙ্গারের ডাইনামিক প্রোগ্রামিং অ্যালগরিদম (Selinger Algorithm, IBM 1979):
1. সার্চ স্পেসকে সংকুচিত করতে মূলত **Left-Deep Trees** বিবেচনা করা হয়।
2. সাব-প্রবলেম মেমোইজেশন:
   - প্রথমে প্রতিটি একক টেবিল $\{T_1\}, \{T_2\}, \dots, \{T_N\}$-এর সবচেয়ে সস্তা অ্যাক্সেস পাথ (Index Scan vs Seq Scan) বেছে নেওয়া হয়।
   - এরপর ২-টেবিল জয়েনের শ্রেষ্ঠ প্ল্যান খোঁজা হয়: $\{T_1, T_2\}, \{T_1, T_3\} \dots$।
   - ৩-টেবিল জয়েন খোঁজার সময় পূর্বে সংরক্ষিত ২-টেবিল অপ্টিমাল রেজাল্ট রিইউজ করা হয়।
   - জটিলতা $O(N!)$ থেকে কমে $O(N \cdot 2^N)$-এ নেমে আসে!

## ৪. ফিজিক্যাল জয়েন অ্যালগরিদমের গভীর ডিস্ক I/O বিশ্লেষণ

ধরা যাক দুটি টেবিল $R$ এবং $S$।
- $B_R$ এবং $B_S$ হলো তাদের ডিস্ক ব্লকের সংখ্যা।
- বাফার পুলে মোট $M$ টি মেমোরি পেজ বরাদ্দ আছে।

```
                                  [ PHYSICAL JOIN MECHANISMS ]
                                               |
        +--------------------------------------+--------------------------------------+
        |                                      |                                      |
[ 1. Block Nested Loop Join ]           [ 2. Grace Hash Join ]                  [ 3. Sort-Merge Join ]
  - মেমোরির M-2 পেজ R দিয়ে পূর্ণ করে      - ছোট টেবিল মেমোরিতে না ধরলে           - উভয় টেবিল জয়েন কি-তে সর্ট করে
    S-এর ১ পেজ দিয়ে স্ক্যান।             ডিস্কে K হ্যাশ বাকেটে পার্টিশন।           টু-পয়েন্টার লিনিয়ার মার্জ।
  - I/O Cost: B_R + (B_R / (M-2)) * B_S  - I/O Cost: 3 * (B_R + B_S)             - I/O Cost: 3 * (B_R + B_S) (with sort)
```

### ১. ব্লক নেস্টেড লুপ জয়েন (Block Nested Loop Join):
মেমোরির $M - 2$ টি পেজ আউটার টেবিল $R$ দিয়ে পূর্ণ করা হয় এবং ১টি পেজ রাখা হয় ইনার টেবিল $S$-এর ব্লক লোড করার জন্য।
- ডিস্ক I/O ব্যয়:
  $$\text{Cost}_{\text{BNL}} = B_R + \left\lceil \frac{B_R}{M - 2} \right\rceil \times B_S$$

### ২. গ্রেস হ্যাশ জয়েন (Grace Hash Join - Out-of-Core Hash Join):
যখন ছোট টেবিল $R$ বাফার পুল মেমোরির চেয়ে অনেক বড় হয়:
1. **Partition Phase:** একটি হ্যাশ ফাংশন $h_1$ দিয়ে উভয় টেবিল $R$ এবং $S$-কে ডিস্কের $K$ টি আলাদা আলাদা বাকেটে বিভক্ত করে ফেলা হয় ($B_R$ এবং $B_S$ পড়তে ও লিখতে মোট $2(B_R + B_S)$ ডিস্ক I/O)।
2. **Build & Probe Phase:** প্রতিটি পেয়ার্ড বাকেট ($R_i$ এবং $S_i$) মেমোরিতে তুলে সাধারণ হ্যাশ জয়েন চালানো হয় (ডিস্ক থেকে পড়তে অতিরিক্ত $B_R + B_S$ I/O)।
- **মোট ডিস্ক I/O খরচ:**
  $$\text{Cost}_{\text{Grace}} = \mathbf{3 \times (B_R + B_S)}$$

### ৩. সর্ট-মার্জ জয়েন (Sort-Merge Join):
1. উভয় টেবিলকে এক্সটার্নাল মার্জ সর্ট দিয়ে সাজানো হয় ($2 \times B \times \lceil \log_{M-1}(B) \rceil$)।
2. সর্টেড টেবিল দুটিকে এক পাসে মার্জ করা হয় ($B_R + B_S$)।
- যদি উভয় টেবিলে ইতিমধ্যে জয়েন কি-এর ওপর B+ Tree ইনডেক্স থাকে, তবে সর্টিং খরচ শূন্য ($0$) হয় এবং **জয়েন খরচ মাত্র $B_R + B_S$ ডিস্ক I/O-তে সম্পন্ন হয়!**

## ৫. সম্পূর্ণ সংখ্যাগত হ্যান্ড-ক্যালকুলেশন: সিলেক্টিভিটি ও কস্ট এস্টিমেশন

ধরা যাক একটি ডাটাবেস টেবিল `Customers` এবং `Orders`:
- `Customers` ($C$): ১০,০০০ রো, ৫০০ পেজ ($B_C = 500$)। `city` কলামে ৫০টি স্বতন্ত্র শহর আছে ($V(\text{city}, C) = 50$)।
- `Orders` ($O$): ১,০০,০০০ রো, ৪,০০০ পেজ ($B_O = 4000$)। `amount` কলামের রেঞ্জ $০ থেকে $১০০০।

কুয়েরি:
```sql
SELECT * FROM Customers C 
JOIN Orders O ON C.id = O.customer_id 
WHERE C.city = 'Chittagong' AND O.amount > 800;
```

### ধাপ ১: সিলেক্টিভিটি ও মধ্যবর্তী আউটপুট সাইজ নির্ণয়
1. **Customers সিলেক্টিভিটি:**
   $$\text{Sel}(C.\text{city} = \text{'Chittagong'}) = \frac{1}{V(\text{city}, C)} = \frac{1}{50} = \mathbf{0.02} \; (2\%)$$
   ফিল্টার্ড গ্রাহক সংখ্যা:
   $$10000 \times 0.02 = \mathbf{200 \text{ সারি (Tuples)}}$$
2. **Orders সিলেক্টিভিটি:**
   $$\text{Sel}(O.\text{amount} > 800) = \frac{1000 - 800}{1000 - 0} = \frac{200}{1000} = \mathbf{0.20} \; (20\%)$$
   ফিল্টার্ড অর্ডার সংখ্যা:
   $$100000 \times 0.20 = \mathbf{20000 \text{ সারি (Tuples)}}$$

### ধাপ ২: অপটিমাইজেশন সিদ্ধান্ত
যদি সিলেকশন পুশডাউন না করা হতো, তবে ১ কোটি জয়েন পেয়ার তৈরি হতো!
সিলেকশন পুশডাউন করার পর ফিল্টার্ড গ্রাহক মাত্র ২০০ জন (যা র্যামের ১টি সিঙ্গেল পেজে ধরে যায়)। অপটিমাইজার সাথে সাথে **ইন-মেমোরি হ্যাশ জয়েন** বেছে নেবে এবং মাত্র কয়েক মিলিসেকেন্ডে সমগ্র কুয়েরি সম্পন্ন করবে!

## ৬. ইন্টারভিউ প্রশ্নোত্তর (MNC Interview Checklist)

1. **প্রশ্ন: Hash Join বনাম Sort-Merge Join কখন বেছে নেওয়া হয়?**
   - **উত্তর:** সমতা জয়েন (`ON A.id = B.id`) এবং আন-সর্টেড বিশালাকার টেবিলের ক্ষেত্রে **Hash Join** সবচেয়ে দ্রুতগতিসম্পন্ন ($O(|A| + |B|)$)। কিন্তু যদি জয়েন শর্ত একটি রেঞ্জ হয় (`ON A.id < B.id`), অথবা ডেটা ইতিমধ্যে B+ Tree ক্লাস্টার্ড ইনডেক্সের কারণে সর্টেড থাকে, অথবা কুয়েরির শেষে `ORDER BY` ক্লজ থাকে, তখন **Sort-Merge Join** শতভাগ ক্ষেত্রে Hash Join-কে পরাজিত করে।
2. **প্রশ্ন: Correlated Subquery কেন একটি মারাত্মক অ্যান্টি-প্যাটার্ন?**
   - **উত্তর:** সাধারণ সাবকুয়েরি কেবল একবার এক্সিকিউট হয়। কিন্তু Correlated Subquery আউটার কুয়েরির কলামের ওপর নির্ভর করে। ফলে আউটার টেবিলের প্রতি একক রো-এর জন্য ইনার সাবকুয়েরিটি বারবার নতুন করে এক্সিকিউট হয় ($O(N \cdot M)$)। অপটিমাইজার প্রায়শই এটিকে আন-নেস্ট (Unnest) করে সাধারণ `JOIN`-এ রূপান্তর করার চেষ্টা করে।
3. **প্রশ্ন: কুয়েরি অপটিমাইজারে Dynamic Programming ব্যর্থ হলে কী মেকানিজম ব্যবহার করা হয়?**
   - **উত্তর:** যখন কুয়েরিতে জয়েন করা টেবিলের সংখ্যা ১২-১৫ অতিক্রম করে ($N > 12$), তখন ডাইনামিক প্রোগ্রামিং মেমোরি ও সময়ের অভাবে এক্সপ্লোড করে। এই পরিস্থিতিতে PostgreSQL-এর মতো আধুনিক ডেটাবেস **GEQO (Genetic Query Optimizer)** প্রয়োগ করে—যা ডারউইনের জেনেটিক অ্যালগরিদম (মিউটেশন ও ক্রসওভার) ব্যবহার করে লক্ষ কোটি প্ল্যানের মধ্যে সবচেয়ে সম্ভাবনাময় প্ল্যানটি খুঁজে বের করে।
