## 🧠 ১. মেমরি ম্যানেজমেন্ট ফান্ডামেন্টালস ও এমএমইউ (MMU & Addressing)

কম্পিউটার সিস্টেমে প্রতিটি প্রসেসের কাছে একটি নিরবচ্ছিন্ন, প্রাইভেট এবং বিশাল মেমরি স্পেস প্রদর্শিত হয় যাকে **লজিক্যাল বা ভার্চুয়াল অ্যাড্রেস স্পেস (Virtual Address Space)** বলা হয়। কিন্তু ফিজিক্যাল র‍্যামের অ্যাড্রেস স্পেস সম্পূর্ণ আলাদা এবং খণ্ডিত (Fragmented)।

```
[ CPU Core ]
     |
     | (Emits Virtual / Logical Address: 0x7FFF5FBFF8A0)
     v
[ Memory Management Unit (MMU) ] <-----+ (Page Table Walk via CR3 Register)
     |                                 |
     +---> Checks Translation Lookaside Buffer (TLB)
     |
     | (Translates to Physical Address: 0x1A4008A0)
     v
[ L1 / L2 / L3 CPU Cache ]
     |
     v (Cache Miss)
[ Main Memory (DRAM RAM Chips) ]
```

### হার্ডওয়্যার বেস ও লিমিট রেজিস্টার (Base and Limit Registers)
ভার্চুয়াল মেমরি আবিষ্কারের পূর্বে মেমরি প্রটেকশনের জন্য হার্ডওয়্যার দুটি রেজিস্টার ব্যবহার করত:
- **Base Register:** প্রসেসটির জন্য বরাদ্দ ফিজিক্যাল মেমরির প্রারম্ভিক অ্যাড্রেস।
- **Limit Register:** প্রসেসটির মোট অনুমোদিত মেমরি রেঞ্জ বা সাইজ।
$$\text{If } (\text{Logical Address} < \text{Limit}) \implies \text{Physical Address} = \text{Base} + \text{Logical Address}$$
$$\text{Else } \implies \text{Trap: General Protection Fault (\#GP)}$$

## 🧱 ২. কনটিগুয়াস মেমরি অ্যালোকেশন ও ফ্র্যাগমেন্টেশন (Contiguous Allocation)

প্রাচীন ওএসে প্রতিটি প্রসেসকে র‍্যামের একটি একটানা (Contiguous) ব্লকে রাখা হতো। এতে দুই ধরনের গুরুতর অপচয় দেখা যায়:

```
+-------------------------------------------------------------------------+
|                  PHYSICAL RAM FRAGMENTATION                             |
+-------------------+-------------------+-------------------+-------------+
| Process 1 (Alloc) | Free Hole (10 MB) | Process 2 (Alloc) | Free (15 MB)|
+-------------------+-------------------+-------------------+-------------+
```

### ক. ফ্র্যাগমেন্টেশনের শ্রেণিবিভাগ
১. **ইন্টারনাল ফ্র্যাগমেন্টেশন (Internal Fragmentation):**
   - যখন প্রসেসকে তার প্রয়োজনের চেয়ে বড় একটি ফিক্সড ব্লক দেওয়া হয়। ব্লকের অব্যবহৃত ভেতরের মেমরি নষ্ট হয়।
   - *উদাহরণ:* প্রসেস চেয়েছে $4097$ বাইট, ওএস তাকে $8192$ বাইটের (বা দুটি ৪কেবি পেজ) ব্লক দিল। বাকি $4095$ বাইট ইন্টারনাল ফ্র্যাগমেন্টেশনে নষ্ট।
২. **এক্সটারনাল ফ্র্যাগমেন্টেশন (External Fragmentation):**
   - সিস্টেমে মোট পর্যাপ্ত ফ্রি মেমরি আছে, কিন্তু তা ছোট ছোট খণ্ডে বিভক্ত থাকায় কোনো নতুন প্রসেসকে একটানা বরাদ্দ দেওয়া যাচ্ছে না।

### খ. ডাইনামিক স্টোরেজ অ্যালোকেশন স্ট্র্যাটেজি
- **First Fit:** মেমরির শুরু থেকে স্ক্যান করে যে প্রথম ফাঁকা গর্তে প্রসেসটি আঁটবে সেখানেই বরাদ্দ দেওয়া (দ্রুততম)।
- **Best Fit:** সমস্ত ফ্রি গর্ত খুঁজে ক্ষুদ্রতম যে গর্তে প্রসেসটি আঁটবে সেখানে বরাদ্দ দেওয়া (ক্ষুদ্রতম অবশিষ্ট গর্ত তৈরি করে, এক্সটারনাল ফ্র্যাগমেন্টেশন বেশি)।
- **Worst Fit:** সবচেয়ে বড় ফাঁকা গর্তে বরাদ্দ দেওয়া (বড় অবশিষ্ট গর্ত থাকে যা হয়তো পরে অন্য কাজে লাগতে পারে, কিন্তু বাস্তবে বাজে পারফর্ম করে)।

> **The 50-Percent Rule (গাণিতিক সত্য):**
> স্ট্যাটিস্টিক্যাল অ্যানালাইসিস প্রমাণ করে যে, First-Fit ব্যবহার করে যদি $N$ টি মেমরি ব্লক বরাদ্দ থাকে, তবে ফ্র্যাগমেন্টেশনের কারণে প্রায় $0.5 N$ সংখ্যক ব্লক অব্যবহৃত অবস্থায় নষ্ট হয়ে থাকে! অর্থাৎ মোট মেমরির এক-তৃতীয়াংশ (৩৩%) এক্সটারনাল ফ্র্যাগমেন্টেশনে অপচয় হতে পারে।

## 📐 ৩. সেগমেন্টেশন (Segmentation) বনাম পেজিং

- **সেগমেন্টেশন:** প্রোগ্রামারের মেমরি ভিউকে মডেল করে (কোড সেগমেন্ট, ডেটা সেগমেন্ট, স্ট্যাক সেগমেন্ট, ইত্যাদি)। প্রতিটি সেগমেন্টের আকার পরিবর্তনশীল।
  - অ্যাড্রেস ফরম্যাট: $\langle \text{Segment Number } s, \text{ Offset } d \rangle$।
  - *সীমাবদ্ধতা:* সেগমেন্টের সাইজ ডায়নামিক হওয়ায় এক্সটারনাল ফ্র্যাগমেন্টেশন এড়ানো যায় না।
- **পেজিংয়ের উত্থান:** এই কারণে আধুনিক x86-64 লং মোডে হার্ডওয়্যার সেগমেন্টেশন মূলত ডিজেবল করে দেওয়া হয়েছে (Flat Memory Model: Base=0, Limit=$2^{64}-1$) এবং সম্পূর্ণ মেমরিকে **পেজিং (Paging)** দ্বারা পরিচালনা করা হয়।

## 📄 ৪. পেজিং ফান্ডামেন্টালস (Paging Architecture)

পেজিং হলো নন-কনটিগুয়াস মেমরি অ্যালোকেশন পদ্ধতি যা এক্সটারনাল ফ্র্যাগমেন্টেশনকে ১০০% দূর করে।
- **ফিজিক্যাল মেমরি** বিভক্ত থাকে ফিক্সড সাইজের ব্লকে যার নাম **ফ্রেম (Frames)**।
- **লজিক্যাল মেমরি** বিভক্ত থাকে সম-আকারের ব্লকে যার নাম **পেজ (Pages)**।
- আধুনিক অপারেটিং সিস্টেমে স্ট্যান্ডার্ড পেজ সাইজ হলো **4 Kilobytes ($4096$ Bytes $= 2^{12}$ Bytes)**।

```
VIRTUAL ADDRESS: [ Page Number (p) ] [ Offset (d) ]
                         |                 |
                         v                 |
                  +--------------+         |
                  |  PAGE TABLE  |         |
                  +--------------+         |
                  | Page p -> f  |         |
                  +--------------+         |
                         |                 |
                         v                 v
PHYSICAL ADDRESS: [ Frame Number (f) ] [ Offset (d) ]
```

### অ্যাড্রেস ট্রান্সলেশন ফর্মুলা:
যদি ভার্চুয়াল অ্যাড্রেস স্পেস $m$-বিট হয় এবং পেজ সাইজ $2^n$ বাইট হয়:
- **অফসেট বিট ($d$):** $n$ টি বিট (৪কেবি পেজের জন্য $n = 12$ বিট)।
- **পেজ নাম্বার বিট ($p$):** $m - n$ টি বিট।

## ⚡ ৫. ট্রান্সলেশন লুকাসাইড বাফার (Translation Lookaside Buffer - TLB)

পেজ টেবিল স্বয়ং ফিজিক্যাল র‍্যামে অবস্থান করে। এর মানে হলো একটি সাধারণ ভ্যারিয়েবল রিড করতে সিপিইউকে **দুটি মেমরি অ্যাক্সেস** করতে হয়:
১. পেজ টেবিল থেকে ফ্রেম নাম্বার বের করা।
২. ফিজিক্যাল ফ্রেম থেকে আসল ডেটা রিড করা।
এটি সিস্টেমের গতি ৫০% কমিয়ে দিত! এই সমস্যা সমাধানে সিপিইউর মধ্যে একটি অতি দ্রুত হার্ডওয়্যার অ্যাসোসিয়েটিভ ক্যাশ বসানো হয় যার নাম **TLB (Translation Lookaside Buffer)**।

```
Virtual Address (p, d)
        |
        v
  [ TLB LOOKUP ] (Parallel Associative Search in 1 CPU cycle)
        |
   +----+----+
   |         |
(TLB Hit)  (TLB Miss)
   |         |
   |         v
   |    [ Page Table Walk in DRAM ] (Multi-cycle latency: 50-100ns)
   |         |
   |         +---> Update TLB with new (p -> f) mapping
   v         v
[ Physical Frame Address (f, d) ]
```

### ইফেক্টিভ মেমরি অ্যাক্সেস টাইম (EMAT) গাণিতিক ডেরিভেশন:
ধরা যাক:
- $\alpha =$ TLB Hit Ratio (আধুনিক সিস্টেমে সাধারণত $\ge 98\% = 0.98$)
- $T_{\text{TLB}} =$ TLB লুকআপ টাইম ($\approx 1 \text{ ns}$)
- $T_{\text{mem}} =$ ফিজিক্যাল মেমরি এক্সেস টাইম ($\approx 50 \text{ ns}$)

$$\text{EMAT} = \alpha \times (T_{\text{TLB}} + T_{\text{mem}}) + (1 - \alpha) \times (T_{\text{TLB}} + 2 \times T_{\text{mem}})$$

**বাস্তব সংখ্যা দিয়ে হিসাব:**
$$\text{EMAT} = 0.98 \times (1 + 50) + 0.02 \times (1 + 100) = 0.98 \times 51 + 0.02 \times 101$$
$$\text{EMAT} = 49.98 + 2.02 = \mathbf{52.0 \text{ ns}}$$
যেখানে TLB ছাড়া সময় লাগত $100 \text{ ns}$! TLB থাকার ফলে মেমরি অ্যাক্সেস অলমোস্ট সিঙ্গেল-মেমরি ল্যাটেন্সিতে চলে আসে।

## 🌲 ৬. মাল্টি-লেভেল পেজিং (x86-64 4-Level Paging Architecture)

### কেন সিঙ্গেল লেভেল পেজ টেবিল অসম্ভব?
৬৪-বিট সিস্টেমে ৪৮-বিট ভার্চুয়াল অ্যাড্রেস স্পেস ব্যবহৃত হয় ($2^{48} = 256 \text{ TB}$)।
- পেজ সাইজ $= 4 \text{ KB} = 2^{12}$ বাইট।
- মোট পেজের সংখ্যা $= \frac{2^{48}}{2^{12}} = 2^{36}$ পেজ।
- প্রতিটি পেজ টেবিল এন্ট্রি (PTE) সাইজ $= 8$ বাইট।
- **সিঙ্গেল পেজ টেবিলের মোট সাইজ:**
  $$\text{Size} = 2^{36} \times 8 \text{ Bytes} = 2^{39} \text{ Bytes} = \mathbf{512 \text{ Gigabytes!}}$$
প্রতিটি সাধারণ প্রসেসের পেজ টেবিল রাখতেই যদি ৫১২ জিবি র‍্যাম লাগত, তবে কম্পিউটার চালু হওয়াই অসম্ভব ছিল!

### x86-64 ফোর-লেভেল পেজিং সলিউশন (Hierarchical Paging):
লিনাক্স ও x86-64 ৪৮-বিট ভার্চুয়াল অ্যাড্রেসকে ৪টি ৯-বিট লেভেল এবং ১টি ১২-বিট অফসেটে ভাগ করে:
$$48 \text{ Bits} = 9 \text{ (PML4)} + 9 \text{ (PUD)} + 9 \text{ (PMD)} + 9 \text{ (PTE)} + 12 \text{ (Offset)}$$

```
48-Bit Virtual Address:
[ 47 : 39 ]      [ 38 : 30 ]      [ 29 : 21 ]      [ 20 : 12 ]      [ 11 : 0 ]
   9 bits           9 bits           9 bits           9 bits          12 bits
   (PML4)           (PUD)            (PMD)            (PTE)           (Offset)
     |                |                |                |                |
%cr3 |                |                |                |                |
  |  v                |                |                |                |
  +->[ PML4 Table ]   |                |                |                |
           |          v                |                |                |
           +--------->[ PUD Table ]    |                |                |
                            |          v                |                |
                            +--------->[ PMD Table ]    |                |
                                             |          v                |
                                             +--------->[ PTE Table ]    |
                                                              |          |
                                                              v          v
                                                  [ Physical 4KB Frame + Offset ]
```
- **PML4 (Page Map Level 4):** `%cr3` রেজিস্টার এর ফিজিক্যাল অ্যাড্রেস নির্দেশ করে।
- **PUD (Page Upper Directory)**
- **PMD (Page Middle Directory)**
- **PTE (Page Table Entry)**
- **সুবিধা:** প্রতিটি টেবিল নিখুঁতভাবে $2^9 \times 8 \text{ bytes} = 4096 \text{ bytes} = \mathbf{4KB}$ (১টি ফ্রেম)। যে মেমরি রেঞ্জ প্রসেস ব্যবহার করছে না, তার জন্য নিচের লেভেলের কোনো টেবিল মেমরিতে তৈরিই হয় না (Sparse Allocation)। একটি ছোট প্রসেসের জন্য মাত্র কয়েক কিলোবাইট পেজ টেবিলই যথেষ্ট!

## 🐘 ৭. হিউজ পেজেস (Huge Pages: 2MB & 1GB) এবং পারফরম্যান্স অপ্টিমাইজেশন

সাধারণ ৪কেবি পেজের কারণে ডাটাবেস (PostgreSQL, MySQL, Redis) বা বিগ-ডাটা অ্যাপ্লিকেশনে হাজার হাজার পেজ ফল্ট এবং টিএলবি মিস হয়।
- **2MB Huge Page:** PML4 $\to$ PUD $\to$ PMD পর্যন্ত গিয়ে থেমে যায়। PMD এন্ট্রিতে Page Size বিট অন করে দেওয়া হয় এবং সরাসরি ২১-বিট অফসেট ব্যবহার করা হয় ($2^{21} = 2 \text{ MB}$)।
- **1GB Huge Page:** PUD লেভেলেই থেমে গিয়ে ৩০-বিট অফসেট ব্যবহার করা হয় ($2^{30} = 1 \text{ GB}$)।
- **সুবিধা:** একটি সিঙ্গেল TLB এন্ট্রি ৪কেবির বদলে ২ মেগাবাইট ডেটা কভার করতে পারে ($512\times$ TLB Coverage বৃদ্ধি)। এর ফলে মেমরি-ইনটেনসিভ ডাটাবেসের কোয়েরি পারফরম্যান্স ২০% থেকে ৪০% পর্যন্ত বৃদ্ধি পায়!

## 🎯 ৮. শীর্ষ এমএনসি ইন্টারভিউ প্রশ্ন ও সমাধান (MNC Deep Dives)

### Q1: কনটেক্সট সুইচের সময় কেন পুরো TLB ফ্লাশ করতে হয় এবং হার্ডওয়্যার PCID (Process Context ID) এটি কীভাবে সমাধান করে?
**উত্তর:**
- **সমস্যা:** ভার্চুয়াল অ্যাড্রেস `0x400000` প্রসেস $A$-তে ম্যাপ হতে পারে ফ্রেম $10$-এ, কিন্তু প্রসেস $B$-তে ম্যাপ হতে পারে সম্পূর্ণ ভিন্ন ফ্রেম $50$-এ।
- যদি কনটেক্সট সুইচে প্রসেস $A$ থেকে $B$-তে যাওয়ার সময় TLB ফ্লাশ না করা হয়, তবে প্রসেস $B$ ভুল করে প্রসেস $A$-এর ক্যাশড ট্রান্সলেশন ব্যবহার করে ডেটা করাপ্ট বা সিকিউরিটি ভায়োলেট করতে পারে!
- কিন্তু প্রতিটি কনটেক্সট সুইচে পুরো TLB মুছে ফেললে পরবর্তী প্রসেসের প্রথম কয়েক হাজার মেমরি অ্যাক্সেসে চরম TLB Miss হয়।
- **সমাধান - PCID (Process Context Identifier) / ASID (ARM):**
  আধুনিক প্রসেসরে TLB-র প্রতিটি এন্ট্রির সাথে একটি ১২-বিট ট্যাগ যুক্ত থাকে যা প্রসেসের আইডি চিহ্নিত করে:
  $$\text{TLB Entry} = \langle \text{PCID}, \text{Virtual Page Number} \rangle \to \text{Physical Frame}$$
  এর ফলে কনটেক্সট সুইচের সময় **TLB ফ্লাশ করার কোনো প্রয়োজন হয় না!** সিপিইউ শুধু বর্তমান PCID পরিবর্তন করে।

### Q2: ইনভার্টেড পেজ টেবিল (Inverted Page Table) কী এবং এটি কোথায় ব্যবহৃত হয়?
**উত্তর:**
- সাধারণ পেজ টেবিলে প্রতিটি প্রসেসের প্রতি ভার্চুয়াল পেজের জন্য একটি এন্ট্রি থাকে (Process-indexed)।
- **Inverted Page Table:** ভার্চুয়াল পেজের বদলে **ফিজিক্যাল ফ্রেম সংখ্যার সমান সাইজের একটি মাত্র গ্লোবাল টেবিল** পুরো সিস্টেমে থাকে (Frame-indexed):
  $$\text{Table Entry } i = \langle \text{PID}, \text{Virtual Page Number } p \rangle$$
- *সুবিধা:* সিস্টেমের র‍্যাম যত জিবি, পেজ টেবিলের সাইজও ততটুকু ফিক্সড থাকে। প্রসেস সংখ্যা বাড়লেও মেমরি অপচয় হয় না (PowerPC ও UltraSPARC আর্কিটেকচারে ব্যবহৃত হতো)।
- *অসুবিধা:* ভার্চুয়াল অ্যাড্রেস থেকে ফ্রেম খুঁজতে গেলে পুরো টেবিল লিনিয়ার সার্চ করতে হতো ($O(N)$), যা সমাধান করতে অতিরিক্ত ইনভার্টেড হ্যাশ টেবিল দরকার হতো। আধুনিক x86-64 মাল্টি-লেভেল পেজিংকেই স্ট্যান্ডার্ড হিসেবে গ্রহণ করেছে।
